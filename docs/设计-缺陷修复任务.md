# 缺陷修复任务（repair）· 设计附录

版本 v0.1 · 2026-10-27 · 补充主设计文档（docs/设计.md）。本附录的接口与数据格式同样是实现契约。

## 1. 动机

主设计的「规格生成」任务里，模型的输入只有函数签名、依赖声明与功能规格；L2（结构）与 L3（语义）变换都发生在函数体内，模型看不到，所以 L2 / L3 的模型输入与 L1 逐字相同，这两级只对评测侧的项目副本有意义，对模型没有区分度（修复阶段的 open_issues 已指出）。

缺陷修复任务让模型直接阅读混淆后的目标函数：在每一级副本的目标函数里注入一个能被项目测试捕获的缺陷，让模型返回修正后的函数。这样三类混淆都作用在模型读到的代码上：L0 考察模型是否凭记忆还原原函数，L1 去掉名字线索，L2 / L3 进一步改变控制流与表达式的表面形态。两类任务并列报告，就能分别回答「生成是否依赖记忆」和「阅读理解是否依赖表面形态」。

## 2. 任务定义

- 输入：与生成任务相同的依赖上下文（includes / 类型 / 宏 / 全局 / 被调函数原型），加上**该级副本里注入缺陷后的目标函数完整定义**。不给功能规格，不给测试输出，不说明缺陷位置。
- 要求：返回修正后的完整函数定义，签名不变，不新增 `#include`。
- 判定：与生成任务完全相同的 `evaluate`（替换 → 语法检查 → 构建 → 项目测试 → 归因）。通过 = 项目测试全过。

## 3. 变异算子（在 Lk 副本的目标函数体上做，AST 引导，复用 `bench/obfuscate/_edits.py` 的按偏移改写机制）

| 编号 | 算子 | 作用位置 | 改写 |
|---|---|---|---|
| ROR | 关系算子替换 | BINARY_OPERATOR 的 `<` `<=` `>` `>=` `==` `!=` | `<`↔`<=`、`>`↔`>=`、`==`↔`!=` |
| OBO | 差一 | 比较或下标里的整数字面量 n | `n+1` 或 `n-1`（seed 决定） |
| NEG | 条件取反 | IF_STMT / WHILE_STMT / FOR_STMT 的条件 | `c` → `!(c)` |
| LOR | 逻辑算子替换 | `&&` ↔ `\|\|` | |
| AOR | 算术算子替换 | `+`↔`-`、`*`↔`/`（整型与指针加减都允许） | |
| DGS | 删守卫 | 形如 `if (cond) return …;` / `if (cond) { return …; }` / `if (cond) break;` 的单语句 if | 整段删除 |
| DST | 删语句 | 函数体内一条赋值、自增或调用表达式语句（不删 return、不删声明） | 整条删除 |
| RVR | 返回值替换 | `return expr;`（expr 不是字面量 0 / NULL） | `return 0;` 或 `return NULL;`（按返回类型） |

每个算子实现为 `find_sites(func_cursor) -> list[Site]` 与 `apply(src_bytes, site, rng) -> bytes`；Site 记录算子、字节区间、原文本、序号。变异后的函数必须能用 libclang 零 error 重新解析，否则该候选作废。

## 4. 变异体选择与 kill 检查

```
for target in 入选目标:
    for level in L0..L3:
        sites = 所有算子在该级目标函数上的候选位点，按 (算子优先序, 位点序号) 排序
        order = rng(seed, target_id, level).shuffle(sites)，但若 L0 已选定算子 op0，则把算子为 op0 的位点排在最前
        for site in order:
            mutant = apply(site)
            若重新解析有 error：跳过
            ev = evaluate(mutant 作为候选)      # 沙箱：必须编译通过，且在测试阶段失败
            若 ev.stage == 'test' 且 category ∈ {test_fail, runtime_crash, runtime_timeout}：选定，记录 kill_mode；break
            否则（编译失败 / 测试仍通过 = 等价变异体）：计数后继续
        若没有任何位点被杀死：该 (target, level) 标 no_killed_mutant，不出题
```

- 优先序：ROR、NEG、LOR、OBO、DGS、AOR、RVR、DST（前面的更像真实缺陷、更少产生等价变异体）。
- 跨级别一致性：L1–L3 优先复用 L0 选定的算子；记录 `same_operator_as_L0`，报告里按「四级同算子」的目标子集单独给一张表，这是最可比的口径。
- 一个 (target, level) 只出一个变异体。
- 变异体 kill 检查最多尝试 12 个位点，超过则放弃该 (target, level) 并计数（控制沙箱成本：208 × 4 × ≤12 次 evaluate）。

## 5. Prompt

system：You are an experienced C programmer. The function below contains a bug that makes the project's tests fail. Return the corrected function only, as one ```c code block containing the complete definition. Keep the signature. Do not add #include lines. No explanation.

user：依赖上下文（与生成任务相同的小节格式与顺序）→ `Buggy function:` → 代码块 → 约束行（C 标准、禁止的头与调用）。模板常量与 `PROMPT_VERSION`、`PROMPT_DIGEST` 分开命名（`REPAIR_PROMPT_VERSION = "repair-v1"`、`REPAIR_PROMPT_DIGEST`）。

## 6. 评测与指标

- 与生成任务共用 evaluate / attribute / similarity；结果记录增加 `task: "repair"`、`mutation: {operator, site_index, original_text, mutated_text}`、`kill_mode`、`unchanged`（候选与变异体规范化后相同，即模型什么也没改）、`restored`（候选与该级原函数规范化后相同，即逐字还原）。
- 指标：按 model × level（× corpus）的通过率、归因分布、`unchanged` 率、`restored` 率、候选与原函数的相似度；「四级同算子」子集的通过率单独给表；按算子分层的通过率。
- 生成任务与修复任务在 summary 里是两张并列的表，报告开头说明两者的输入差异。

## 7. 数据文件

- `results/mutants-<corpus>-<level>.jsonl`：target_id、level、operator、site_index、original_text、mutated_text、mutant_code（完整函数）、kill_mode、tried_sites、equivalent_count、compile_fail_count、input hashes。
- `results/tasks-repair.jsonl`、`results/generations-repair-<model>.jsonl`、`results/results-repair-<tag>.jsonl`：结构与生成任务对应文件一致，多 `task` 与 `mutation` 字段。

## 8. 模块与接口

```python
# bench/mutate.py
@dataclass

OPERATORS: tuple[str, ...]   # 优先序

REPAIR_PROMPT_VERSION, REPAIR_PROMPT_DIGEST
def build_repair_messages(task: RepairTask) -> list[dict]
# bench/pipeline.py / cli.py（新增阶段与参数）
```

MockLLM 增加两种 repair 用模式：`oracle` 对 repair 任务返回该级原函数（必须 100% pass）；`unchanged` 返回变异体原样（必须 100% 不通过且 unchanged=True）。

## 9. 测试要求

- `tests/test_mutate.py`：每个算子的最小用例（源码进、变异后源码出、重新解析零 error）；mini 夹具上 choose_mutant 对每个目标至少找到一个被杀死的变异体，且等价变异体（例如把永远为真的条件取反）被正确计为 equivalent；跨级别优先复用算子的逻辑有用例。
- `tests/test_e2e_mock.py` 扩展：repair 任务 oracle 100% pass、unchanged 100% fail 且 unchanged=True、broken 100% compile_syntax。
- 现有 1583 个测试必须保持全绿。

## 10. 验收

- mini 夹具与 9 个真实语料：`mutate` 跑完，每个语料的 (target, level) 出题率、放弃数、算子分布、`same_operator_as_L0` 比例写进 `docs/实验记录.md` 新增一节。
- e2e mock 三类断言成立；全量 pytest 全绿。

## 11. 局限（写进 README）

- 变异体是人工注入的单点缺陷，不等于真实缺陷分布；不同级别的变异体不一定是同一个缺陷（有 `same_operator_as_L0` 子集作可比口径）。
- 不给测试输出，难度高于真实场景中的修复；通过率绝对值不可与其它基准比较，只看级别间的差异。
- 崩溃型与超时型杀死的目标，其测试不检查返回内容，修复后只要不崩溃即通过（与生成任务相同的局限，报告按 kill_mode 分层）。
